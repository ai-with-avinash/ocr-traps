<objective>
Set up an engagement metrics tracker and a reply-template library so the distribution surface (LinkedIn, Medium, Reddit, HN, GitHub Issues, email) can be monitored and responded to consistently without ad-hoc effort each time a comment surfaces.

Purpose: Without a tracker, distribution outcome becomes invisible — there is no honest record of whether the LinkedIn / Reddit / HN posts converted to GitHub stars, Zenodo downloads, endorsement-candidate replies, or new collaborators. Without a reply-template library, every hostile question / endorsement nibble / journalist outreach is answered from scratch under emotional pressure, which produces inconsistent tone and slow turnaround. Both artifacts are low-cost and parallel-safe (don't block 03-01 or 03-02).

Output: A daily-snapshot metrics file with simple counters, plus a reply-template library covering the four most likely inbound conversation classes (hostile question, technical clarification, endorsement offer/lead, journalist/community-organizer outreach).
</objective>

  <action>
    Create a markdown file with four labeled reply templates, each in its own section. Each section header names the conversation class, then includes: a 1-sentence trigger description (when to use it), a TEMPLATE block with placeholder text, and 1-2 short notes on tone or pitfalls.

    Class 1 — "Hostile / dismissive critique" (e.g. "this is just train/test contamination, not novel"). Template should: concede the principle in the first sentence, name the contribution explicitly (magnitude / mechanism / protocol), link the relevant section of the paper or Medium piece, close with an invitation for further critique. Use the phrasing already worked out in the Kornai reply (see commit 8833b78). Pitfall note: never argue back — concede first, then narrow.

    Class 2 — "Technical clarification" (e.g. "what was the Wilcoxon test power at n=20?"). Template should: answer specifically with the number and source artifact (results/expanded_gt_metrics/statistical_tests.json), link the regenerable command (python tools/recompute_metrics.py), invite the asker to reproduce. Pitfall: don't bluff numbers — if you don't know, say "let me check the artifact and reply within 24h".

    Class 3 — "Endorsement offer / lead" (e.g. "I'd be happy to endorse" OR "you should ask X"). Template should: thank, send the endorsement code RDOS9I + URL https://arxiv.org/auth/endorse?x=RDOS9I + PDF attachment ~/Desktop/ocr-traps-seethalam-2026.pdf, confirm category cs.DL primary with cs.CV + cs.IR cross-list. Pitfall: respond within 4 hours — endorsement enthusiasm decays fast.

    Class 4 — "Journalist / community-organizer outreach" (e.g. "we'd like to feature this in our newsletter / podcast / conference"). Template should: thank, confirm the speaker availability + venue category (practitioner-facing only, not academic conferences yet), link the press kit (which does not exist yet — note this as a TODO in the template). Pitfall: do not over-commit on speaking before the arXiv preprint is live.

    Avoid: AI-sounding phrasing ("I appreciate your thoughtful engagement"), unnecessary apologies, rambling. Each template body should be under 6 sentences.
  </action>
